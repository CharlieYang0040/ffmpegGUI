# 안정화 감사 기준선

최종 갱신: 2026-08-27
기준 커밋: `446a660` + 0.1.4 안정화 작업 트리

## 판정 원칙

이 문서는 기능 추가 기록이 아니라 실제 사용 가능성을 판정하는 기준선이다. 컴파일 성공,
단위 테스트 통과, UI 노출 또는 과거 개발 계획의 체크 표시는 기능 완성의 증거로 사용하지
않는다. 상태는 다음 여섯 가지로만 기록한다.

- **미구현**: 선언이나 UI만 있고 동작 경로가 없다.
- **단절**: UI, 모델, 미리보기, 저장, 출력 중 일부만 연결됐다.
- **부분 동작**: 제한된 자동 입력에서만 확인됐다.
- **오동작**: 결과 또는 저장 상태가 계약과 다르다.
- **불안정**: 크래시, 멈춤, 경쟁 조건 또는 간헐 실패가 있다.
- **검증 완료**: 명시된 실제 사용 시나리오를 반복 통과했다.

## 핵심 수직 흐름

1차 안정화 범위는 `실행 → CFR/VFR 가져오기 → 첫 프레임 → 재생/seek → 기본 편집 →
undo/redo → 저장/재실행/불러오기 → CPU H.264 출력 → FFprobe 검증`이다. 고급 컬러,
HDR, 스코프와 Unreal 전달은 핵심 흐름을 깨뜨리지 않는지만 확인하고 별도 게이트로 둔다.

|---|---|---|---|

| 패키지·클린 PC | 미검증 | 개발 PC 런타임 배치 | 별도 Windows 11 x64 설치·실행 |

## 상태 소유권과 위험 경계

- `TimelineModel`이 클립, 자산, 자막, 마커와 undo/redo의 단일 진실 공급원이다.
- `EditorController`의 QVariant 캐시는 QML 투영일 뿐이며 모델 변경이나 선택 변경 즉시
  폐기되어야 한다. QML 알림과 프리뷰 재구축만 타이머로 병합할 수 있다.
- import, float preview, scope, export와 GES 작업은 각각 세대 번호와 취소/종료 수명을
  가져야 하며 오래된 완료 콜백이 최신 상태를 덮어쓰면 안 된다.
- D3D11 texture는 Scene Graph 렌더 스레드 수명에 종속된다. 장치 제거 복구는 별도
  실기 게이트이며 CPU fallback 성공 전까지 GPU 자원을 재사용하지 않는다.
- 저장과 출력은 UI 캐시가 아니라 모델 스냅샷을 사용하고, 성공 검증 전 원본이나 최종
  출력 경로를 교체하지 않는다.

## 1차 완료 게이트

- Debug/Release 클린 빌드와 자동 테스트 신규 경고 없이 통과
- 핵심 수직 흐름 10회 연속 통과
- 실행·프로젝트 로드·종료 20회 반복에서 크래시와 잔류 프로세스 없음
- 편집 및 재생 soak 각 10분 동안 stall, 상태 불일치, 미리보기 오류와 지속적 메모리 증가 없음
- CPU 기본 경로에서 프레임 전환과 스키밍 표시가 안정적이며, D3D11 opt-in은 별도 실기 게이트를 통과함
- 저장 전후 핵심 편집 상태가 동일하고 출력 영상·오디오·길이가 타임라인과 일치함
- 실패·취소 시 손상 프로젝트와 불완전 출력이 남지 않음

게이트를 모두 통과하기 전에는 정식 릴리스나 전체 기능 완료로 표시하지 않는다.

## 이번 안정화 검증

자동 smoke/soak 통과는 아래 이력으로만 보존하며 실제 UI 안정성의 완료 판정으로 사용하지 않는다.

- 2026-08-27 Computer Use로 Debug 실제 창에서 `test_001.mp4`를 파일 대화상자로 추가했다.
  미디어 카드, 프로그램 모니터와 타임라인 썸네일이 표시됐고 Hover 미리보기를 끈 상태에서
  타임라인 눈금 7.5초 부근을 클릭하자 재생헤드가 `00:00:07.543`/F159로 이동했다. 컬러
  작업 공간에서는 Primary 노드를 열어 Shadow, Midtone, Highlight, Master 네 휠과 영역
  범위 슬라이더를 확인했다.
- 격리형 직접 D3D11의 4-slot fence 풀은 offscreen 실제 Qt Scene Graph 표시 3회 연속,
  EOS 반복 재생, 강제 장치 제거 후 CPU 복구와 전체 데스크톱 smoke를 통과했다. 이는 현재
  RTX/드라이버 조합의 자동·UI 증거이며 물리 TDR 및 다른 GPU 검증을 대체하지 않는다.

- 2026-08-25 실제 Release 창에서 `cfr_30fps_audio.mp4`를 직접 추가한 뒤 썸네일 두 위치
  hover, 재생/정지, 컬러 노드 추가·펼치기·휠 조작, 편집 복귀와 타임라인 seek를 수행했다.
  수정 전에는 `failed to activate bufferpool`, Qt device loss와 2초 UI stall이 반복됐고,
  CPU 안전 기본값 적용 후 같은 흐름에서 UI 소실·검은 화면·stall 없이 마지막 seek가 119ms에 끝났다.

- 같은 실제 창에서 타임라인 분할·삭제·undo·redo를 수행한 뒤 프로젝트를 저장하고 앱의 열기
  대화상자로 다시 불러왔다. 삭제 뒤 남은 1.933초 클립과 미디어 연결이 그대로 복원됐다.

- 내보내기 진입부의 `preview_watcher_.waitForFinished()`와 UI 스레드 `player_->stop()`을 제거했다.
  수정 Release 창에서 저장 프로젝트를 열고 클립 복제로 미리보기 재구성을 유발한 뒤 내보내기를
  눌렀으며 입력/화면 갱신 왕복은 245ms였다. 출력은 2클립 3.866666초 스냅샷으로 시작해
  FFprobe 3.866667초 검증을 통과했고, 이 실행 구간에는 event-loop stall이나 preview 오류가 없었다.
  짧은 NVENC 작업은 취소 입력 전에 완료되어 실제 취소 판정에는 사용하지 않는다.

- CTest 2/2 통과
- 핵심 라운드트립과 CPU H.264 출력 3회 연속 통과
- 전체 데스크톱 스모크 통과: 프로젝트 왕복, 출력, JKL, 소스 편집, managed color,
  D3D11 표시와 CPU fallback
- 편집 soak 600초 통과: 2,398작업, 구조 편집 178회, 최대 작업 17ms,
  최대 UI 지연 297ms, 전달 프레임 4,819개, preview 오류 0
- 4K seek: H.264 중앙값 163.208ms/최대 229.554ms, HEVC 중앙값 96.131ms/최대
  130.585ms
- 4K 혼합 재생 soak는 사용자 요청에 따라 약 6분에서 중단했으며 그전까지 오류 출력이나
  조기 종료는 없었다. 10분 완료 증거로 간주하지 않는다.
- 접힌 grade 본문 Loader 적용 뒤 동일 프로젝트 왕복에서 89ms 이상 color-preview UI 차단
  경고가 재발하지 않았고 단축 핵심 왕복을 통과했다.
- 직접 D3D compositor에서 장치 손실을 재현했고, system compositor와 CPU color 강제 경로에서는
  같은 손실이 재현되지 않아 직접 compositor를 명시적 진단 opt-in으로 격리했다. 장치 제거
  시뮬레이션은 QSG texture wrapper를 native texture와 device보다 먼저 렌더 스레드에서 폐기한 뒤
  D3D decoder를 비활성화하고 CPU appsink 첫 프레임까지 복구하는 반복 회귀 3/3을 통과했다.
  실제 드라이버·GPU별 물리 TDR/장치 제거 검증은 별도 게이트다.
- lazy grade UI 적용 뒤 60초 단축 편집 soak 통과: 239작업, 구조 편집 16회, 최대 구조 편집
  8ms, 최대 UI 지연 140ms, 전달 프레임 642개, preview 오류 0.
- Release 전체 빌드와 CTest 2/2를 통과했고, Release 핵심 프로젝트 왕복과 CPU H.264 출력
  1회를 영상·오디오·길이 검증까지 통과했다.
