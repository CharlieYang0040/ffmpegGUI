# 미디어 미리보기 구조와 완료 기록

최종 갱신: 2026-07-30

## 상태

기존 FFmpeg 직접 디코딩 스레드에서 Qt 기반 미리보기로의 전환은 완료됐다.
현재 배포 기준과 검증 명령은
[development_plan.md](development_plan.md)를 따른다.

## 현재 구조

### 비디오

- `QMediaPlayer`, `QAudioOutput`, `QVideoWidget` 사용
- 재생, 일시정지, 속도 변경과 프레임 seek 지원
- 플레이어 시간과 선택 클립의 소스 프레임을 상호 변환
- 소스 전환과 앱 종료 시 플레이어 상태와 출력을 정리

### 이미지와 이미지 시퀀스

- Qt 이미지 로더 스레드와 제한된 프레임 버퍼 사용
- 파일명의 시작 번호를 내부 0-based 인덱스로 변환
- 손상 프레임은 기록 후 건너뛰고 다음 정상 프레임에서 재동기화
- 직접 seek한 프레임을 읽지 못하면 미리보기 오류로 표시
- 시퀀스의 실제 파일 수를 목록, 타임라인과 인코딩에서 공유

### 애니메이션 WebP

- Pillow가 프레임 시간을 제공하지 않는 경우 WebP ANMF 청크를 읽어 실제
  프레임 시간을 복구
- 프레임 시간, 총 길이와 인코딩 FPS를 회귀 테스트로 보호

## 상태 연결

```text
목록 선택
  → 미디어 메타데이터 로드
  → WorkspaceState 선택 클립 갱신
  → 미리보기 소스 변경
  → CutTimelineWidget 프레임/구간 갱신
```

미리보기와 인코딩은 같은 `ClipRange` 의미를 사용한다. 미디어 로딩 중
타임라인의 임시 기본값이 목록의 저장된 트림을 덮어쓰지 않으며, 로딩이
끝나면 저장 구간을 복원한다.

## 검증된 시나리오

- CFR/VFR 영상의 재생, 일시정지와 seek
- 0.5x, 2.4x 재생 속도
- 영상과 24프레임 PNG 시퀀스 반복 전환
- 시작 번호 `0001`, `1001` 시퀀스
- 손상 이미지 프레임 skip과 재동기화
- 트림된 CPU/NVENC 출력 재생
- 취소 후 플레이어·FFmpeg·작업 스레드 종료
- 패키징 실행 파일 시작 스모크

## 후속 확장 후보

4K 이미지 시퀀스의 장시간 메모리와 프레임 드롭 계측은 2.0 배포 차단
사항이 아니다. 버퍼 크기나 선행 로딩 정책을 변경할 때 별도 성능 기준과
고정 샘플을 마련한다.
