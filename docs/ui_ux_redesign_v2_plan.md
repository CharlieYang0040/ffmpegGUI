# ffmpegGUI UI/UX 재설계 V2 계획

작성일: 2026-07-30

> 완료 상태: 2026-07-30에 V2 범위를 구현하고 2.0 기준선에 통합했다.
> 현재 완료 조건과 검증 명령은
> [development_plan.md](development_plan.md)를 기준으로 한다.

## 1. 재설계 목표

이번 수정은 기존 화면의 색상과 여백만 다듬는 작업이 아니다. 현재의
`소스 / 미리보기 / 결과` 폼 세 개를 나란히 배치한 인상을 줄이고, 영상 편집
도구처럼 미디어와 결과를 보면서 컷의 순서와 사용 구간을 직접 조작할 수 있는
작업 공간으로 바꾼다.

핵심 원칙:

- 설명 문구보다 화면 구조와 아이콘, 컨트롤 위치로 사용법을 전달한다.
- 일반 텍스트는 한 가지 기본 색을 사용한다. 보조색은 상태, 비활성, 시간 정보에만 쓴다.
- 컷 편집은 하단 타임라인에서 보이고 조작되어야 한다.
- 기본 창 크기에서 가로·세로 스크롤 없이 핵심 작업을 완료할 수 있어야 한다.
- Premiere Pro나 Final Cut Pro의 정보 구조를 참고하되, 다중 트랙 편집기의
  복잡성은 가져오지 않는다.

## 2. 현재 화면에서 확인된 문제

### 시각 체계

- 앱 부제와 각 패널 설명이 서로 다른 회색으로 표시되어 화면이 산만하다.
- `빠른 변환과 프레임 단위 컷 편집`, `변환하거나 이어 붙일 파일`,
  `사용할 프레임 범위를 확인하세요` 같은 문장이 기능보다 먼저 보인다.
- 패널, 그룹 박스, 입력 필드에 경계선이 반복되어 화면이 여러 겹의 상자로 보인다.
- 파란색이 선택, 체크, 버튼, 탭에 동시에 강하게 사용되어 우선순위가 약하다.

### 레이아웃

- 1280×760 초기 크기에서 결과 패널의 입력 필드와 버튼이 잘리고 가로
  스크롤이 생긴다.
- 800×600 최소 크기는 실제 콘텐츠가 요구하는 크기보다 작다.
- 세 패널을 같은 높이로 나란히 놓아 미리보기 면적과 결과 패널 너비가 모두 부족하다.
- 진행 상태가 항상 큰 영역을 차지해 편집 화면의 세로 공간을 줄인다.

### 소스 패널

- 탭 코너에 고정된 `➕` 버튼이 탭 높이 및 여백 체계와 맞지 않아 밖으로 튀어나온다.
- 탭 닫기, 새 시퀀스, 파일 추가의 위계가 불명확하다.
- 빈 상태 문장이 크고 흐리며, 주 작업인 파일 추가 버튼과 분리되어 있다.

### 미리보기와 컷 편집

- 현재 타임라인은 80px짜리 프레임 눈금과 세 개의 작은 마커에 가깝다.
- 선택 구간이 얇은 띠로만 보이고 클립의 순서, 길이, 분할 결과가 보이지 않는다.
- 재생 속도 슬라이더가 컷 편집보다 큰 비중을 차지한다.
- 프레임 스핀박스는 오른쪽 결과 패널에 있어 영상과 편집 범위의 관계가 끊긴다.
- 타임라인 좌표 계산이 마커·페인트·마우스 처리마다 중복되어 경계 표시가
  한 프레임씩 어긋날 가능성이 있다.

## 3. 새 화면 구조

기본 창은 `1440×900`을 목표 크기로 사용한다. 실제 화면의 사용 가능 영역이
작으면 최대화하며, 마지막 정상 창 위치와 크기를 기억한다.

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ ffmpegGUI                                      FFmpeg ●   설정           │
├──────────────┬──────────────────────────────────────┬────────────────────┤
│ 소스         │                                      │ 출력               │
│              │               뷰어                   │ 프리셋             │
│ 시퀀스 탭  + │                                      │ 저장 위치          │
│ 클립 목록    │                                      │ 핵심 옵션          │
│              ├──────────────────────────────────────┤ 실행 전 상태        │
│ + 미디어     │  ⏮  ◀  ▶  ▶|   00:00:12:08   1.0x  │ [내보내기]         │
├──────────────┴──────────────────────────────────────┴────────────────────┤
│ 컷 타임라인  [clip 1────────][clip 2────][clip 3────────────]            │
│ 시간 눈금          │재생 헤드      선택 영역/트림 핸들                  │
├──────────────────────────────────────────────────────────────────────────┤
│ 준비됨 · 클립 3개 · 00:00:18:12                           로그          │
└──────────────────────────────────────────────────────────────────────────┘
```

화면 역할:

- 소스: 시퀀스와 클립 관리만 담당한다.
- 뷰어: 영상 확인과 재생 제어만 담당한다.
- 출력: 프리셋, 저장 위치, 필수 옵션, 실행 전 문제와 내보내기만 담당한다.
- 컷 타임라인: 클립 순서, 길이, 선택, 재생 위치, 트림과 분할을 담당한다.
- 상태 바: 진행률과 결과를 한 줄로 표시하며 상세 로그는 필요할 때만 연다.

## 4. 시각 디자인 체계

### 글자와 색

- 제목, 필드명, 일반 문장은 동일한 기본 글자색을 사용한다.
- 패널의 설명 문장은 제거한다.
- 흐린 색은 타임코드, 부가 메타데이터, 비활성 컨트롤에만 사용한다.
- 강조색은 선택 클립, 포커스, 주요 실행 버튼에만 사용한다.
- 성공·경고·오류 색은 작은 상태 아이콘과 한 줄 메시지에만 사용한다.
- 앱 헤더의 부제를 제거하고 `ffmpegGUI`만 표시한다.

### 표면과 경계

- 바깥 패널의 두꺼운 카드 테두리를 없애고 배경 명도 차이로 영역을 구분한다.
- 그룹 박스 중첩을 제거한다. 필드 간 8px, 섹션 간 16px 간격을 적용한다.
- 모서리 반경은 4~6px로 통일한다.
- 입력 필드는 기본 상태에서 약한 경계, 포커스 상태에서만 강조색 경계를 사용한다.
- 이모지 버튼을 제거하고 일관된 단색 SVG 아이콘을 사용한다.

### 컨트롤 규격

- 기본 행 높이 32px, 작은 도구 버튼 28×28px, 주요 버튼 36px로 통일한다.
- 시퀀스 추가 버튼은 `QTabWidget` 코너 위젯 대신 탭 헤더 내부의 28×28
  `QToolButton`으로 만든다.
- 모든 버튼은 레이아웃의 size hint를 따르고 화면 밖으로 돌출되는 고정 크기를 없앤다.

## 5. 컷 타임라인 V2

기존 `TimelineWidget`을 수정해서 연장하지 않고, 편집 전용
`CutTimelineWidget`으로 교체한다.

### 표시 요소

- 전체 출력 시간을 나타내는 상단 시간 눈금
- `EditSequence` 순서대로 이어진 단일 비디오 트랙
- 각 `EditClip`을 길이에 비례한 둥근 클립 블록으로 표시
- 클립 이름과 가능한 범위에서 썸네일 필름스트립 표시
- 선택 클립은 강조 테두리, 비선택 클립은 동일 계열의 낮은 명도 사용
- 현재 프레임의 세로 재생 헤드와 상단 손잡이
- 선택 클립 양 끝의 In/Out 트림 핸들
- 트림 중 원본 프레임과 결과 길이를 툴팁 및 작은 오버레이로 표시
- 클립 사이의 컷 지점을 명확한 1px 경계로 표시

### 조작

- 빈 위치 클릭: 재생 헤드 이동
- 클립 클릭: 목록과 뷰어의 선택을 함께 변경
- 클립 본문 드래그: 순서 변경
- 좌우 가장자리 드래그: `ClipRange.source_in/source_out` 변경
- 재생 헤드에서 분할: 도구 버튼 또는 `Ctrl+K`
- `Delete`: 선택 클립 삭제
- `Ctrl+D`: 선택 클립 복제
- 마우스 휠: 가로 이동, `Ctrl+휠`: 확대/축소
- `I`, `O`: 현재 재생 위치를 선택 클립의 시작/끝으로 설정
- 드래그 중에는 미리보기 프레임과 결과 길이를 실시간 갱신하되,
  실행 취소 기록은 마우스를 놓을 때 하나의 명령으로 만든다.

### 상태 연결

`WorkspaceState.edit_sequence`를 타임라인의 유일한 편집 데이터로 사용한다.

```text
CutTimelineWidget 사용자 입력
        ↓
TimelineEditIntent
        ↓
WorkspaceState 명령(split / move / delete / range update)
        ↓
EditSequence 변경
        ↓
소스 목록 · 뷰어 · 출력 길이 · EncodingJob 동시 갱신
```

픽셀과 프레임 변환은 `TimelineGeometry` 한 곳에서 담당한다. 그리기, 히트
테스트, 드래그가 같은 변환 함수를 사용하도록 해 경계 오차를 막는다.

### 범위 제한

- 단일 비디오 트랙만 제공한다.
- 전환 효과, 자막, 오디오 믹싱, 다중 트랙은 추가하지 않는다.
- 첫 버전의 썸네일 필름스트립은 화면에 보이는 클립만 비동기로 생성·캐시한다.

## 6. 영역별 정리

### 앱 바

- 부제 제거
- FFmpeg 상태는 작은 점과 `준비됨` 텍스트로 축소
- 설정은 단색 아이콘 버튼으로 변경
- 앱 바 높이를 44px로 고정

### 소스

- `1. 소스`와 설명 문장을 `소스` 한 줄로 단순화
- 시퀀스 탭과 추가 버튼의 높이를 동일하게 맞춤
- 탭 닫기는 선택 탭에서만 노출
- 빈 상태는 작은 아이콘과 `미디어 추가` 버튼만 표시
- 하단에는 `미디어 추가` 주 버튼과 더보기만 남기고 별도 삭제 버튼은
  키보드 및 컨텍스트 메뉴로 이동

### 뷰어

- 패널 제목과 설명을 제거해 영상 면적을 늘림
- 재생 버튼을 중앙 아이콘 도구 막대로 변경
- 현재 타임코드를 중앙에 고정폭 글꼴로 표시
- 재생 속도는 슬라이더 대신 `1.0x` 팝업 메뉴로 축소
- 영상이 없을 때는 검은 뷰어와 작은 추가 아이콘만 표시

### 출력

- `3. 결과`와 설명 문장을 `출력`으로 단순화
- 자동 출력/파일명/폴더명 체크박스 세 개를 하나의 이름 규칙 메뉴로 통합
- FPS·해상도 고정은 `추가 설정` 접이식 영역으로 이동
- 프레임 컨트롤은 출력 패널에서 완전히 제거
- 실행 전 확인은 정상일 때 한 줄 상태만 표시하고 문제 발생 시 해결 버튼을 노출
- `인코딩 시작`은 `내보내기`로 명칭을 단순화하고 패널 하단에 고정

### 진행과 로그

- 큰 진행 그룹 박스를 제거한다.
- 하단 상태 바에 작업명, 진행률, 남은 상태와 취소 버튼을 표시한다.
- 로그는 우측 하단의 `로그` 버튼으로 여는 오버레이 패널로 변경한다.
- 완료 후 행동은 상태 바 위의 작은 토스트/액션 바에 표시한다.

## 7. 창 크기와 반응형 정책

- 최초 실행: 사용 가능 화면의 90% 범위에서 최대 `1440×900`
- 화면이 1366×768 이하이거나 Windows 배율로 사용 가능 영역이 작으면 최대화
- 이후 실행: 마지막 창 위치·크기·최대화 상태 복원
- 안전 최소 크기: 실제 레이아웃 검증 후 `1180×720` 수준으로 설정
- 1180px 미만에서는 억지로 세로형으로 바꾸지 않고 출력 인스펙터를
  우측 슬라이드 패널로 전환
- 패널별 최소 폭: 소스 240px, 뷰어 520px, 출력 300px
- 저장된 splitter 값이 최소 폭을 깨면 기본 비율로 자동 복구
- 100%, 125%, 150%, 200% 배율에서 논리 픽셀 기준으로 검증

## 8. 구현 순서

### Phase 1 — 화면 골격과 시각 체계

- 설명 문구와 부제 제거
- 텍스트 색, 여백, 아이콘, 컨트롤 높이 통일
- 앱 바와 소스 탭 버튼 정리
- 초기 창 크기·최대화·복원 정책 적용
- 결과 패널의 가로 잘림 제거

완료 조건:

- 1366×768 125% 환경의 최초 실행에서 핵심 컨트롤이 잘리지 않음
- 탭 추가 버튼을 포함한 모든 버튼이 패널 경계 안에 위치
- 일반 텍스트가 임의의 회색/파란색으로 섞이지 않음

### Phase 2 — 편집형 작업 공간

- 뷰어 컨트롤을 편집 앱 형태로 재배치
- 결과의 프레임 컨트롤을 제거
- 하단 상태 바와 로그 오버레이 구현
- 소스·뷰어·출력·타임라인의 새 splitter 구조 적용

완료 조건:

- 뷰어가 현재보다 넓고, 타임라인이 전체 컷 순서를 표시할 충분한 폭을 확보
- 파일 추가부터 내보내기까지 세로 스크롤 없이 기본 작업 가능

### Phase 3 — `CutTimelineWidget`

- `TimelineGeometry`와 클립 블록 렌더링 구현
- 선택, seek, 트림 핸들, 분할, 삭제, 복제, 재정렬 연결
- 목록·뷰어·타임라인 선택 동기화
- undo/redo 명령 단위 정리

완료 조건:

- 두 개 이상의 클립이 길이에 비례해 한 트랙에 표시됨
- 트림 핸들을 움직이면 화면의 범위와 실제 인코딩 프레임이 일치
- 분할 후 두 블록 길이의 합이 기존 길이와 일치
- 목록과 타임라인 어느 쪽에서 선택해도 다른 화면이 동일 클립을 가리킴

### Phase 4 — 썸네일·확대 및 마감

- 보이는 구간만 생성하는 타임라인 썸네일 캐시
- 가로 스크롤, 확대/축소, 긴 시퀀스 대응
- 키보드 포커스, 툴팁, 고대비 상태 정리

- 색상 없이도 선택, 재생 위치, 오류 상태를 구분할 수 있음

## 10. 이번 재설계에서 제거할 항목

- 앱 부제 및 패널 설명 문구
- 출력 패널의 프레임 스핀박스
- 큰 진행 상태 그룹 박스
- 현재의 얇은 마커형 `TimelineWidget`
- 탭 밖으로 돌출된 이모지 `➕` 버튼
- 기본 화면의 중첩 그룹 박스와 불필요한 테두리

이 계획은 기존 인코딩 엔진과 `ClipRange` 모델을 유지하면서 UI와 편집 상호
작용을 재구성한다. 화면 목업만 만든 뒤 연결을 미루지 않고, 각 Phase를 실제
상태와 명령에 연결된 동작 단위로 완료한다.
